🎯 演算法教學重點整理

貪心、掃描線、分治、動態規劃——點選下面的主題，就能看到那個主題由淺入深的教學內容！

貪心演算法：由淺入深的 5 個重點，一步步看懂「每次都選當下最好」的解題思路。

1什麼是貪心演算法？入門

「貪心演算法」聽起來很兇，其實意思很簡單：每一步都選「現在看起來最好」的選擇，選了就不後悔、不回頭。

🍬 生活例子：吃到飽夾菜 去吃到飽，你可能會想「先夾我現在最想吃的東西」，夾一輪之後再夾下一輪最想吃的。這就是貪心：每一步都選當下最好的，不會想太多以後的事。

換代幣的例子

少林寺有四種代幣：50元、10元、5元、1元。如果要換 123 元，最少要用幾個代幣？

50
10
5
1

貪心的做法：先盡量用最大的面額換，換不下去了再換小一點的。

💰 換 123 元 123 = 50×2（用掉100） + 10×2（用掉20） + 1×3（用掉3）
總共用了 2+2+3 = 7 個代幣，這是最少的方法！

這個方法之所以行得通，是因為 50、10、5、1 這幾種面額搭配得剛剛好（比如 5 個 1 元就能換 1 個 5 元），所以每次拿最大的都不會吃虧。

2貪心不是每次都對！入門

⚠️ 小心！換個代幣面額，貪心就會出錯 如果代幣面額變成 1、4、5，要換 8 元：
  • 貪心做法：先拿一個 5 元，剩 3 元只能拿 3 個 1 元 → 用了 4 個代幣
  • 但其實用兩個 4 元就湊成 8 元了 → 只要 2 個代幣！
所以貪心找到的答案是「4 個」，比正確答案「2 個」還要多，貪心在這裡失敗了。

這告訴我們一個很重要的觀念：用貪心解題前，要先想清楚「每次選當下最好的」是不是真的能保證最後結果最好。有些問題可以證明貪心一定對，有些不行，需要動腦筋想一想或用其他方法（例如動態規劃）。

3優先佇列：誰最急就先處理誰基礎

排隊本來是「先來先服務」，但醫院掛號不是這樣，病情越緊急的人，會被排到越前面，這種「依照重要程度排隊」的方式，就叫做優先佇列（Priority Queue）。

🏥 生活例子：急診室 急診室不是誰先到就先看，而是最嚴重的病人優先。優先佇列就像一個會自動幫你把「最重要/最小/最大」的東西放在最前面的排隊系統，隨時有新的人加進來，它也能馬上重新排好順序。

在程式裡，優先佇列常常用一種叫「堆（heap）」的方法實作，Python 有現成的工具（heapq）可以直接用，不用自己蓋輪子。

4貪心演算法的經典例子進階

🥋 比武配對：怎麼贏最多場

兩隊高手要一對一比武，戰力高的贏。你可以自己安排誰打誰，希望贏越多場越好。

做法 每次找「我方最弱的人」和「對方最弱的人」比：如果我方能贏，就派他上場；如果贏不了，這個弱者就先放棄，換下一個弱者試試看。

⏳ 排隊做事：怎麼讓大家等最少

有好幾件工作要做，每件花的時間不同，大家都要等到輪到自己才能開始。要怎麼排順序，讓「每個人等待時間加起來」最少？

做法：越快做完的，排越前面 比如四件工作要花的時間是 3、1、3、4 分鐘。
如果照 (1,3,3,4) 的順序做，完成時間分別是 1、4、7、11，加起來 23 分鐘，這是最短的！
道理很簡單：先做「花時間少」的事，可以讓後面排隊的人少等一點。

🎬 排電影場次：怎麼看最多場

有很多場活動，每場都有開始和結束時間，同時間只能參加一場，你想參加越多場越好。

做法：先挑「最早結束」的那一場 為什麼？因為越早結束，留給你之後可以參加的場次就越多！挑完一場後，跳過所有跟它時間重疊的場次，繼續挑下一個最早結束的。
場次A 1~4
場次B 0~3 ✅先選
場次C 3~4
場次D 4~6 ✅再選

上面例子中，先選「B (0~3)」再選「D (4~6)」，剛好可以參加兩場，是最多的了。

5貪心 + 二分搜：先猜答案再檢查進階

有些題目問「最小可以是多少」，如果直接想很難算，我們可以改用「猜答案」的方式：

🏗️ 生活例子：蓋幾座基地台才夠涵蓋大家？ 假設題目問：基地台的訊號範圍最小要多大，才能用固定數量的基地台涵蓋所有的點？

做法是：先猜一個訊號範圍，然後用貪心的方法檢查「這個範圍夠不夠用」——如果基地台數量夠，代表範圍可以再小一點；如果不夠，代表要再大一點。像玩「猜數字」遊戲一樣，越猜越接近正確答案，這就是二分搜。

簡單說：猜一個答案 → 用貪心的方法檢查行不行 → 根據結果調整猜的方向，這樣可以很快找到最好的答案。

e576 線段覆蓋：完整題解

題目：給定多組線段 [Li, Ri]，用最少數量的線段完全覆蓋 [0, M]，如果無法覆蓋則輸出 0。

📋 點我展開／收合完整題解程式碼 
# e576 線段覆蓋：貪心（每次選「能延伸最遠」的線段）
import sys

def solve():
    data = sys.stdin.read().split()
    idx = 0
    T = int(data[idx]); idx += 1   # 測資組數
    outputs = []
    for _ in range(T):
        m = int(data[idx]); idx += 1   # 要覆蓋 [0, m]
        segs = []
        while True:
            l, r = int(data[idx]), int(data[idx+1]); idx += 2
            if l == 0 and r == 0:   # l=r=0 代表這組線段輸入結束
                break
            segs.append((l, r))
        segs.sort()   # 依左端點排序，才能由左到右掃描

        i = 0
        n = len(segs)
        current_end = 0   # 目前已經覆蓋到哪裡
        selected = []
        ok = True
        while current_end < m:
            best_r = current_end
            best_idx = -1
            # 在「左端點 <= 目前覆蓋到的位置」的線段中，挑「能延伸最遠」的那條
            while i < n and segs[i][0] <= current_end:
                if segs[i][1] > best_r:
                    best_r = segs[i][1]
                    best_idx = i
                i += 1
            if best_idx == -1:
                ok = False   # 沒有線段能再往右延伸，代表蓋不滿 [0, m]
                break
            selected.append(segs[best_idx])
            current_end = best_r

        if not ok:
            outputs.append("0")
        else:
            lines = [str(len(selected))]
            for l, r in sorted(selected):
                lines.append(f"{l} {r}")
            outputs.append("\n".join(lines))
    print("\n\n".join(outputs))

solve()

c575 基地台：完整題解

題目：在數線上有 N 個服務點，架設 K 座直徑相同的基地台，每座基地台可以涵蓋一段連續區間，求可以涵蓋所有服務點的最小直徑。

📋 點我展開／收合完整題解程式碼 
# c575 基地台：貪心 + 二分搜
# 讀入服務點數量 n 與基地台數量 k
n, k = map(int, input().split())
p = list(map(int, input().split()))
p.sort()  # 先排序，才能從左到右用貪心的方式檢查

# 檢查：如果每座基地台的直徑是 d，是否可以用不超過 k 座基地台涵蓋所有點
def enough(d):
    count = 0          # 目前用了幾座基地台
    last_covered = -1  # 目前為止涵蓋範圍的右端點（一開始還沒涵蓋，設一個不可能的值）
    for x in p:
        if x > last_covered:        # 這個點還沒被涵蓋，必須新蓋一座基地台
            count += 1
            last_covered = x + d    # 新基地台從 x 開始，涵蓋到 x+d
            if count > k:           # 用的基地台已經超過 k 座，提早失敗
                return False
    return count <= k

# 對直徑 d 做二分搜，找出最小的可行直徑
lo, hi = 0, p[-1] - p[0]   # 直徑的搜尋範圍：0 到 最大差距
while lo < hi:
    mid = (lo + hi) // 2
    if enough(mid):
        hi = mid        # mid 可行，答案可能可以更小
    else:
        lo = mid + 1     # mid 不可行，答案要更大

print(lo)  # 印出最小可行直徑

掃描線演算法：想像一把尺子從左滑到右，邊滑邊更新答案。

1掃描線演算法：想像一把尺子滑過去基礎

掃描線演算法的意思是：想像有一條線（或一把尺）從左慢慢滑到右邊，滑的過程中，我們一邊記錄目前看到了什麼，一邊更新答案。

📏 線段的總長度：重疊的地方不要算兩次

如果地上畫了好幾條線段，有些會互相重疊，要算出「總共蓋住了多長」，重疊的部分只能算一次。

做法 把所有線段的開始點和結束點都放在一起，由左到右排序。想像尺子從左滑到右，碰到「開始點」就代表這裡開始被蓋住，碰到「結束點」就代表結束。這樣可以一次算出所有被蓋住的長度，不會重複算。

📈 買賣賺最多：只要記住「目前最低價」

每天股票（或商品）價格都不一樣，先買後賣一次，怎麼賺最多？

做法：邊看邊記住「目前為止的最低價」 從第一天開始，每天想：「如果我今天賣掉，最多能賺多少？」也就是「今天的價格」減去「到今天為止看過的最低價格」。把每天算出來的獲利中最大的記下來，就是答案！這樣只要看一次所有的天數，就能算出來，不需要每兩天都去比較。
💡 這其實跟「線段聯集」的想法很像：都是從左到右掃過去，一邊掃一邊更新一個簡單的紀錄（例如目前最低價、目前蓋住的長度），就能又快又準地算出答案，不需要把所有組合都比一遍。

c295 最大和：完整題解

題目：給定 N 群數字，每群 M 個，各群選一個數字加總得到 S，求 S 的最大值，並輸出所選數字中能整除 S 的（依群別順序），若都不能整除則輸出 -1。

📋 點我展開／收合完整題解程式碼 
# c295 最大和：貪心（每群挑最大值，總和自然最大）
n, m = map(int, input().split())
picks = []
for _ in range(n):
    row = list(map(int, input().split()))
    picks.append(max(row))   # 每群只要選最大的那個，總和一定最大

S = sum(picks)
# 找出「選出的數字」中，能整除總和 S 的那些，依群別順序輸出
divisors = [str(x) for x in picks if S % x == 0]

print(S)
print(' '.join(divisors) if divisors else -1)

b966 線段覆蓋長度：完整題解

題目：輸入 N 個線段，計算這些線段總共覆蓋的長度，重疊的部分只能算一次。

📋 點我展開／收合完整題解程式碼 
# b966 線段覆蓋長度：掃描線（差分 / 事件排序）
n = int(input())
events = []  # 每個線段拆成「開始事件」與「結束事件」
for _ in range(n):
    l, r = map(int, input().split())
    events.append((l, 1))    # 在 l 這裡厚度 +1
    events.append((r, -1))   # 在 r 這裡厚度 -1

# 排序規則：座標小的在前；座標相同時，「開始事件」要排在「結束事件」前面，
# 這樣才不會把同一座標的覆蓋長度算漏
events.sort(key=lambda e: (e[0], -e[1]))

total = 0       # 目前累積的總覆蓋長度
thickness = 0   # 目前這個位置被幾條線段蓋住
last = None     # 上一個處理過的座標

for pos, delta in events:
    if thickness > 0 and last is not None:
        # 上一段 [last, pos] 之間有被覆蓋，把長度加進總和
        total += pos - last
    last = pos
    thickness += delta   # 更新目前的覆蓋厚度

print(total)

分治演算法：切一半，各自解決，再合併起來。

1分治演算法：切一半，各自解決，再合併基礎

分治（Divide and Conquer）的精神很簡單：把一個大問題切成兩半，各自先解決小問題，最後把兩邊的答案合併成完整答案。

① 切割
把問題分兩半
→
② 各自求解
（遞迴處理）
→
③ 合併
組合成完整答案
🍕 生活例子：兩個人一起數一大疊考卷 一疊考卷太多了，一個人數要很久。如果分成兩疊，你數一疊、朋友數一疊，最後把兩個數字加起來，就是總數。這就是分治：切一半、各自做、加起來。

📊 合併排序法：邊分邊排序

排序一堆數字時，可以先把數字分成兩半，各自排好序，最後再把兩個已經排好的序列合併成一個。合併兩個已經排好序的隊伍其實很簡單：只要每次比較兩隊最前面的人，把比較小的那個先放進新隊伍，一直比到其中一隊清空為止。

🔍 分治最重要的是「合併」這一步

使用分治法時，切割跟各自求解通常都很簡單（就是呼叫自己去處理一半的資料），真正需要動腦筋的地方是「怎麼把兩邊的答案合併起來」。想清楚合併的方法，整個問題往往就解決了。

🧮 例子：計算逆序對（數列中「前面比後面大」的配對數） 給一排數字，找出所有「前面的數字比後面的數字大」的配對，例如 (3, 1, 9, 8, 9, 2) 裡有 6 組這樣的配對。

直接兩兩比對要花很多時間，但如果用分治：先算左邊自己內部的配對數、算右邊自己內部的配對數，最後只要算「左邊某個數字比右邊某個數字大」的配對數量，而這剛好可以搭配「合併排序法」的合併步驟一起完成，一次處理，非常有效率。
🏆 動手練習（zerojudge） q655. 上菜 (Serving) —— 這一題的核心就是計算逆序對數量，很適合拿來練習分治法的合併技巧。
💡 分治和掃描線常常可以解決同一種問題（例如「線段最近點對」），差別在於：分治通常只需要簡單的陣列就能做到，而掃描線有時需要比較複雜的資料結構。所以遇到問題時，不妨兩種都想想看！

🏆練習題與題解由淺入深

① 基礎：合併排序的合併技巧（自我練習） 先試著自己動手寫一次合併排序法（merge sort），確定自己能正確合併兩個已排序好的陣列，這是所有分治合併題目的基本功。
② 進階：逆序對（APCS 相關概念，分治法原題） q655. 上菜 (Serving) —— 標籤明確標示「分治法／逆序數對」，是本節「合併排序法找逆序對」概念的實戰題。

q655 上菜：完整題解

題目：N 分鐘內，每分鐘廚師做出一道料理（種類 C_i），同時也有一位客人點餐（種類 D_i）。上菜規則是「依照料理做出的先後順序」，同種類料理則「先點的客人先上菜」。當某位客人被排在他後面點餐的人搶先上菜時，怒氣值 +1，請計算所有客人的怒氣值總和。

關鍵想法：把每一次「上菜順序」對應到某一位客人，就會得到一個「客人到達順序 → 被上菜順序」的對應表。而怒氣值總和，其實就是這張對應表裡「逆序對」的數量——這正是分治法（合併排序法）的經典應用！

📋 點我展開／收合完整題解程式碼 
# q655 上菜 (Serving)：分治法（合併排序法計算逆序對）
import sys
from collections import deque

def merge_count(a, le, ri):
    # 計算 a[le:ri] 區間內的逆序對數量，同時把這段區間排序好
    if le + 1 >= ri:
        return 0
    mid = (le + ri) // 2
    w = merge_count(a, le, mid) + merge_count(a, mid, ri)
    temp = []
    i, j = le, mid
    while i < mid and j < ri:
        if a[i] <= a[j]:
            temp.append(a[i]); i += 1
        else:
            temp.append(a[j]); j += 1
            w += mid - i   # 左邊剩下的元素都比 a[j] 大，形成逆序對
    temp.extend(a[i:mid])
    temp.extend(a[j:ri])
    a[le:ri] = temp
    return w

def solve():
    data = sys.stdin.read().split()
    idx = 0
    n = int(data[idx]); idx += 1
    C = [0] * (n + 1)   # 第 m 分鐘做出的料理種類
    D = [0] * (n + 1)   # 第 i 分鐘點餐的料理種類
    for m in range(1, n + 1):
        C[m] = int(data[idx]); D[m] = int(data[idx + 1]); idx += 2

    # 依料理種類，分別把「製作順序」與「點餐順序」排隊
    prod_queue = {}
    arr_queue = {}
    for m in range(1, n + 1):
        prod_queue.setdefault(C[m], deque()).append(m)
    for i in range(1, n + 1):
        arr_queue.setdefault(D[i], deque()).append(i)

    # 同種類料理採 FIFO 配對：第 k 個做出的料理，配給第 k 個點這道菜的客人
    pos = [0] * (n + 1)   # pos[客人到達順序] = 被分配到的製作順序（= 上菜順序）
    for t, aq in arr_queue.items():
        pq = prod_queue[t]
        while aq:
            cust = aq.popleft()
            pos[cust] = pq.popleft()

    # 怒氣值總和 = 「到達順序」與「上菜順序」之間的逆序對數量
    arr = pos[1:]
    print(merge_count(arr, 0, len(arr)))

solve()

1動態規劃是什麼？為什麼最難？入門

動態規劃（Dynamic Programming，簡稱 DP）常常被認為是最難學的演算法主題，原因不是它用到艱深的數學，而是每一題的「思考方式」都不太一樣，很難套公式，需要多做題目累積經驗才能抓到感覺。

⚠️ 為什麼「純遞迴」會太慢？ 舉例：計算「爬樓梯，每次走1階或2階，總共有幾種走法」。如果直接寫遞迴 f(n) = f(n-1) + f(n-2)，程式看起來很簡潔，但是當 n 只是 40，程式就會卡很久；n=100 更是「跑到天荒地老都跑不完」。

原因是：同樣的答案被重複計算了非常多次。例如算 f(40) 時，f(38) 這個答案會被重複算了好幾萬次！

動態規劃要解決的正是這個問題：把算過的答案「記下來」，之後需要用到時直接查表，不要重算。這個概念其實很像我們寫功課時的「小抄」或「查表機」——算過的東西寫在紙上，下次要用就直接看，不用重新算一遍。

📒 生活例子：查電話簿而不是每次都問一遍 如果每次要打電話給同學都要重新問全班同學「誰知道他的電話」，太浪費時間了。不如把問到的電話號碼記在電話簿裡，下次要用直接翻開查，這就是動態規劃「記錄答案」的精神。

2動態規劃的三個步驟入門

設計一個動態規劃解法，通常照著這三個步驟思考：

① 定義子問題
「這題可以拆成哪些比較小的同類型問題？」
→
② 找出遞迴關係
「這個問題的答案，怎麼用小問題的答案算出來？」
→
③ 決定計算順序
「照什麼順序算，才能保證用到的答案都已經算好了？」

前兩步驟其實跟「純遞迴」的想法一樣，真正讓動態規劃變快的關鍵是第三步：把答案存進一個表格，依照順序（通常是由小到大）一步步計算，不再重複呼叫自己。

💡 也有一種偷懶的寫法叫「Top-down（由上而下）」：還是用遞迴寫，但是每次遞迴前先「偷看」表格裡有沒有算過，算過就直接拿現成答案，沒算過才真的去算，算完記得存回表格。這個方法很好寫，但要小心遞迴太深可能會出問題。

3一維問題：爬樓梯基礎

最簡單的一類動態規劃問題，只需要一個一維表格就能解決。

🪜 爬樓梯問題 每一階樓梯都寫著一個「扣分」數字，每次可以走1階或2階，請問走到最後一階，最少總共要扣多少分？

定義 c[i] 為「走到第 i 階的最小扣分」。因為走到第 i 階的最後一步一定是從第 i-1 階或第 i-2 階走過來的，所以：
c[i] = 第i階的扣分 + min(c[i-1], c[i-2])

只要照 i 從小到大的順序，把每一階的答案存進表格裡，最後直接讀出最後一階的答案就好了，完全不需要遞迴！
🏆 動手練習（zerojudge） a519. 12459 - Bees' ancestors —— 這一題是類似費氏數列的一維動態規劃入門題，很適合拿來練習「表格由小到大算」的感覺。

4二維問題：方格路徑、最長共同子字串基礎

有些問題的子問題需要用「兩個數字」來描述（例如格子的座標，或兩個字串各取多長），這時候就需要一個二維表格。

🔤 最長共同子字串（LCS）

給兩個字串，找出「最長的共同子序列」（字母順序要一樣，但可以跳過某些字母）。例如 "algorithm" 與 "alignment" 的最長共同子序列長度是 4（例如 algm）。

做法 比較兩字串的最後一個字母：如果一樣，答案就是「兩邊都去掉最後一個字母的答案」再加1；如果不一樣，答案就是「去掉其中一邊最後一個字母」兩種情況中比較大的那個。用一個二維表格，由左上往右下逐格算，就能算出答案。
🏆 動手練習（zerojudge） a252. Another LCS —— 直接練習最長共同子字串的經典二維動態規劃題目。
💡 順帶一提：像「找一段連續數字的最大總和」這種問題，用分治也能解（把陣列切一半，分別找左邊、右邊、跨過中間的最大和，取最大值），思路可以參考本頁「分治演算法」分頁中的合併技巧。

5背包問題進階

背包問題是動態規劃最經典的題目之一，幾乎每個學動態規劃的人都會碰到它。

🎒 大賣場免費大搬家 你可以在「總重量不超過 W」的限制下，從 n 樣商品中挑選一些帶走（每樣只能選一次，不能只拿一部分），每樣商品都有自己的重量與價值，希望帶走的商品總價值越大越好。

如果只想「前 i 樣物品」的最佳解，會發現新增一樣物品可能讓整個答案大翻盤，很難直接列出遞迴式。這時候的訣竅是多加一個條件：除了「前 i 樣物品」，再加上「重量限制 j」，也就是定義：

d[i][j] = 考慮前 i 樣物品、重量不超過 j 時的最大價值

遞迴關係 對第 i 樣物品，只有兩種選擇：
• 不選它：d[i][j] = d[i-1][j]
• 選它（如果裝得下）：d[i][j] = 這樣物品的價值 + d[i-1][j - 這樣物品的重量]
兩者取比較大的就是答案。
🏆 動手練習（zerojudge） b184. 5. 裝貨櫃問題 —— 標準的 0/1 背包問題，跟上面「大賣場免費大搬家」的做法完全一樣，很適合當作背包問題的第一題練習。

6最長遞增子序列（進階）進階

這一題稍微難一點，但是非常經典，常被簡稱 LIS（Longest Increasing Subsequence）。

📈 例子 給一排數字，找出最長的一段「由左到右挑出來、而且數字越挑越大」的子序列。例如 (2, 4, 1, 3, 6, 4, 6, 9) 中可以挑出 (1, 3, 4, 6, 9)，長度是 5。

最直接的想法：定義 lis(i) 為「以第 i 個數字結尾的最長遞增序列長度」，那麼 lis(i) = 前面比它小的數字中，lis值最大的那個 + 1。這樣寫程式雖然正確，但是每個位置都要往前搜尋一遍，速度不夠快。 更聰明的做法是額外維護一個「目前每種長度，最小可能的結尾數字」的表格，這樣就可以用二分搜快速找到該接在哪裡後面，把速度從「檢查所有組合」大幅加快。

🏆 動手練習（zerojudge） d052. 11456 - Trainsorting —— 直接練習最長遞增子序列（LIS），是體會「動態規劃搭配二分搜可以加速」的好題目。

7階梯數字（挑戰題）挑戰

這一題被公認是比較難想的動態規劃題目，放在這裡讓大家看看「難的動態規劃」長什麼樣子，不用擔心一次就要完全學會。

🔢 階梯數字 如果一個正整數「從左到右看，每一位數字只會不變或變大」，就稱為階梯數字，例如 123、234、777。給一個數字 N，請計算不超過 N 的階梯數字總共有多少個。

這一題的關鍵想法是：先算出一個表格 step[i][j]，代表「以數字 j 開頭的 i 位階梯數字總共有幾個」，再依照輸入的 N，一位一位去累加表格裡對應的數字。因為每多一位數字時，能接在後面的數字只能「不小於前一位」，所以表格可以用一個簡單的規律，由位數少往位數多、由大數字往小數字，逐步計算出來。

這一題告訴我們：不是所有動態規劃的子問題都直接對應題目給的資料，有時候需要先設計一個「輔助表格」，把數字拆解成位數來思考，才找得到規律。這也是動態規劃困難的地方——找到正確的子問題定義，往往比寫程式本身還要花時間。

🏆 動手練習（zerojudge） c543. 四、階梯數字(ladder) (APCS 加強題) —— 就是這一題的原題，非常適合挑戰看看，感受一下困難動態規劃題目的思考過程。

8學動態規劃的建議總結

✏️先寫出「純遞迴」版本，確定遞迴關係式是對的，再想辦法改成表格或加上小抄（memo），不要一開始就想直接寫出最有效率的版本。

🧩如果「定義子問題」時發現遞迴式列不出來，通常代表子問題的定義「條件不夠多」，可以試著多加一個條件（就像背包問題多加了「重量限制」這個條件）。

📚多做幾題經典題型（爬樓梯、方格路徑、LCS、背包、LIS），把它們的思考方式記起來，很多新題目其實是這些經典題的變化版。

🐢不用急著求快，先求對。能正確跑出答案的暴力解，也是找到規律、設計動態規劃的重要線索。

① a519 蜜蜂祖先數：一維DP

輸入多行世代數 n（以 0 結束），輸出第 n 代的祖先數量。第 n 代祖先數 = 第 n-1 代 + 第 n-2 代（跟費氏數列一樣的遞迴關係）。

📋 點我展開／收合完整題解程式碼 
# a519 蜜蜂祖先數：一維DP（費氏數列變形）
import sys

MAXN = 80
# 先把 1~80 代的祖先數全部算好，存進表格 anc[]
anc = [0] * (MAXN + 1)
anc[1] = 1
anc[2] = 2
for i in range(3, MAXN + 1):
    anc[i] = anc[i-1] + anc[i-2]  # 遞迴關係：跟前兩代的祖先數相加

for line in sys.stdin:

    if line == '':
        continue
    n = int(line)
    if n == 0:      # 輸入 0 代表結束

    print(anc[n])

② a252 三字串最長共同子序列：二維DP的延伸（三維）

輸入三個字串，求三者共同的最長子序列長度。做法是把課文中兩字串的 LCS 遞迴式，多加一個維度變成三個字串版本。

📋 點我展開／收合完整題解程式碼 
# a252 三字串的最長共同子序列（LCS）：三維DP
s1 = input().strip()
s2 = input().strip()
s3 = input().strip()
l1, l2, l3 = len(s1), len(s2), len(s3)

# dp[i][j][k]：s1前i個字、s2前j個字、s3前k個字的LCS長度
dp = [[[0] * (l3 + 1) for _ in range(l2 + 1)] for _ in range(l1 + 1)]

for i in range(1, l1 + 1):
    for j in range(1, l2 + 1):
        for k in range(1, l3 + 1):
            if s1[i-1] == s2[j-1] == s3[k-1]:
                # 三個字元都相同，可以接在一起，LCS長度加1
                dp[i][j][k] = dp[i-1][j-1][k-1] + 1
            else:
                # 至少捨棄其中一個字串的最後一個字元，取最大值
                dp[i][j][k] = max(dp[i-1][j][k], dp[i][j-1][k], dp[i][j][k-1])

print(dp[l1][l2][l3])

③ b184 裝貨櫃問題：0/1 背包

輸入包含多筆測資直到檔案結尾，每筆測資有 n 項貨物與體積、利潤，貨櫃總容量固定是 100，求最大利潤總和。

📋 點我展開／收合完整題解程式碼 
# b184 裝貨櫃問題：0/1背包（一維滾動陣列版本）
import sys

def solve():
    data = sys.stdin.read().split()
    idx = 0
    results = []
    while idx < len(data):
        n = int(data[idx]); idx += 1
        w = [0] * n  # 每項貨物的體積
        p = [0] * n  # 每項貨物的利潤
        for i in range(n):
            w[i] = int(data[idx])
            p[i] = int(data[idx + 1])
            idx += 2
        W = 100  # 貨櫃總容量固定是100
        # dp[j]：容量剛好可用 j 時，可以獲得的最大利潤
        dp = [0] * (W + 1)
        for i in range(n):
            # j 要由大到小更新，確保每項貨物最多只被選一次（0/1背包的關鍵）
            for j in range(W, w[i] - 1, -1):
                dp[j] = max(dp[j], dp[j - w[i]] + p[i])
        results.append(str(dp[W]))
    print('\n'.join(results))

solve()

④ d052 火車調度：最長遞增子序列（LIS）

輸入多筆測資，每筆有 n 節車廂與重量，求最長「重量遞增」的子序列長度。用二分搜將複雜度優化到 O(n log n)。

📋 點我展開／收合完整題解程式碼 
# d052 火車調度：最長遞增子序列（LIS），二分搜優化版
import bisect
import sys

def solve():
    data = sys.stdin.read().split()
    idx = 0
    T = int(data[idx]); idx += 1
    out = []
    for _ in range(T):
        n = int(data[idx]); idx += 1
        w = [int(data[idx + i]) for i in range(n)]
        idx += n
        # tails[k]：長度為 k+1 的遞增子序列中，最小可能的結尾值
        tails = []
        for v in w:
            pos = bisect.bisect_left(tails, v)  # 找出可以接在哪裡
            if pos == len(tails):
                tails.append(v)   # 可以接得比原本都長，長度+1
            else:
                tails[pos] = v    # 用更小的結尾值替換，讓未來更容易接更長
        out.append(str(len(tails)))
    print('\n'.join(out))

solve()

⑤ c543 階梯數字：數位DP（挑戰題）

輸入多行正整數 N（可能非常大，最多約 30 幾位數），對每一行輸出不超過 N 的階梯數字個數，答案要模 1e9+7。

📋 點我展開／收合完整題解程式碼 
# c543 階梯數字：數位DP (Digit DP)
import sys

MOD = 10**9 + 7

def count_stepping(nstr):
    n = [int(ch) for ch in nstr]   # 把N的每一位數字拆開存成陣列
    L = len(n)
    # step[i][j]：i 位數、最高位（開頭）是 j 的階梯數字個數
    step = [[1] * 10 for _ in range(L + 1)]
    step[1][0] = 0  # 0不是階梯數字，其餘1~9的一位數各算1個（已經是預設值1）

    # 遞迴關係：step[i][j] = step[i][j+1] + step[i-1][j]（尾端往前的後綴和）
    for i in range(2, L + 1):
        for j in range(8, -1, -1):
            step[i][j] = (step[i][j + 1] + step[i - 1][j]) % MOD

    # 神奇的地方：step[i][0] 這一格，剛好等於「所有位數比 i 少」的階梯數字總數
    # （因為遞迴式會一路累加回去），所以不需要另外再加一次，否則會重複計算！
    total = sum(step[L][:n[0]]) % MOD  # 開頭比N第一位小的部分（含比N位數少的所有情況）
    is_stepping = True   # N本身是不是階梯數字
    for i in range(1, L):
        if n[i] < n[i - 1]:
            is_stepping = False
            break
        # 前面位數已經跟N一樣，這一位選「比N這一位小」的所有可能
        total = (total + sum(step[L - i][n[i - 1]:n[i]])) % MOD
    if is_stepping:
        total = (total + 1) % MOD   # N自己也是階梯數字，別忘了加1

    print(total % MOD)

for line in sys.stdin:
    line = line.strip()
    if line:
        count_stepping(line)

四個主題的重點濃縮版，快速複習用。

📝重點總整理

🎯 貪心演算法

🎯核心概念：每一步都選「現在看起來最好」的答案，簡單直覺，但不是每個問題都適用，用之前最好想一想或證明看看。

🏥優先佇列：像急診室一樣，讓「最重要 / 最小 / 最大」的東西永遠排在最前面，方便隨時取用。

📊排序是貪心的好朋友：很多貪心題目第一步都是先排序（例如照時間短到長、照結束時間早到晚）。

🔍貪心 + 二分搜：遇到「最小的○○是多少」這種問題，可以先猜答案，再用貪心的方法檢查猜得對不對，越猜越準。

📏 掃描線演算法

📏想像一條線從左滑到右，邊滑邊更新答案，常常搭配排序使用，能很有效率地解決「線段」「區間」「連續一段」的問題。

✂️ 分治演算法

✂️把問題切一半、各自遞迴求解、再合併答案。重點通常在「合併」這一步要怎麼做才快，常跟合併排序法、逆序對等問題有關。

🧩 動態規劃

🧩先把大問題拆成小問題（子問題），找出「答案怎麼用小問題答案算出來」的遞迴關係，再決定計算順序（由小到大）把答案存進表格，避免暴力遞迴的重複計算。

🎒常見經典題型：爬樓梯（一維）、方格路徑與最長共同子字串（二維）、背包問題（多加條件）、最長遞增子序列（進階＋二分搜優化）。

🐢學習訣竅：先求對（純遞迴），再求快（表格化）；多做經典題累積思考模式。
